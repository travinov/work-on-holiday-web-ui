# Руководители и реестр сотрудников

## Импорт

Администратор: **Пользователи → Импорт реестра сотрудников и руководителей** (`/admin/roster`). Доступны шаблоны CSV и Excel `.xlsx`. Заголовки:

| ФИО сотрудника | Рабочая почта сотрудника | Рабочая почта руководителя |
| --- | --- | --- |
| Иванов Иван Иванович | ivanov@example.org | |
| Петров Пётр Петрович | petrov@example.org | ivanov@example.org |

Поддерживаются CSV UTF-8 / Windows-1251 с разделителями запятая, точка с запятой или табуляция; XLSX — первый лист. Лимиты: 5 МБ, 10000 строк сотрудников, 30 МБ распакованного Excel. Макросы и старый формат XLS не поддерживаются.

1. Загрузите файл и проверьте предпросмотр. Изменения ещё не применены.
2. Почта сопоставляется без учёта регистра. Существующие записи обновляются; новые создаются. ФИО не используется для автоматического связывания.
3. Если найдено совпадающее ФИО без почты, явно выберите существующую запись либо создание другого человека. Затем обновите предпросмотр. Связывание сохраняет ключ, историю задач, токен, грейд, статус и независимые права администратора.
4. Дубли почты, неизвестные руководители и циклы блокируют применение всего файла. Руководитель может быть в другом месте файла либо в существующем справочнике с почтой. Дубли почты в старой базе требуют исправления справочника до импорта.
5. Нажмите «Применить». Применение атомарно; при изменении справочника после предпросмотра требуется новая загрузка. Предпросмотр принадлежит создавшему его администратору, действует 24 часа и применяется один раз.

Пустая почта руководителя снимает подчинение. Отсутствующие в файле сотрудники не удаляются, их руководитель не меняется. Смена рабочей почты не трактуется как автоматический перенос личности: для такого случая требуется отдельная проверка администратором.

Для новых импортированных сотрудников администратор выдаёт токены через существующую кнопку выдачи/перевыпуска на странице «Пользователи». Самостоятельно получить первый токен такой записи по ФИО нельзя. Вход — по рабочей почте и токену; при уникальном ФИО доступен и прежний вход по ФИО. Тёзки входят по почте. Самостоятельная регистрация вне реестра сохраняется.

## Руководитель

Наличие хотя бы одного прямого подчинённого автоматически даёт доступ к `/manager` и ссылку «Задачи команды» в кабинете. Удаление последней связи снимает этот доступ. Роль не заменяет администратора; заблокированный/архивированный руководитель не может войти.

- По умолчанию: прямые подчинённые и текущая календарная неделя (понедельник–воскресенье).
- Все уровни: руководители ниже и их сотрудники на любой глубине, группировка задач по непосредственному руководителю.
- Предыдущая/следующая неделя, выбранная неделя либо включительный диапазон плановых дат. Используются актуальные даты и тексты с учётом корректировок.
- Поиск по ФИО, множественный выбор сотрудников и подстрока описания задачи без учёта регистра. Пустой выбор — вся доступная команда.
- Кнопки над формой: «Сохранить фильтр» открывает окно ввода названия и сохраняет текущие условия формы, «Применить фильтр» открывает список личных фильтров с действиями применения и удаления. Для ручного обновления списка используется «Показать задачи». Окна закрываются кнопкой или Escape.
- Последние применённые фильтры и именованные подборки сохраняются в БД учётной записи и доступны при входе с другого компьютера. Повторное имя обновляет подборку; подборку можно удалить. «Текущая неделя» хранится как относительный период и движется по календарю сервера.
- При смене структуры доступ пересчитывается. Сохранённый выбор бывших подчинённых не раскрывает данные; устаревший выбор отмечается на экране. Явное применение формы обновляет выбор.
- Список без задач учитывает период и фильтры сотрудников, но не поиск текста. Отменённая заявка считается существующей. Отсутствие заявок не означает отсутствия выхода на работу.
- Подробности задачи доступны только для действующей подчинённой структуры; изменение чужих задач руководителю не добавлено. Собственные задачи остаются в `/employee`.

## Миграция и эксплуатация

При обычном старте приложения создаются три дополнительные таблицы: `app_org_employee`, `app_team_filter`, `app_roster_draft`, плюс индекс руководителя. Старые ключи и данные не переписываются. Для новых сотрудников ключ — отдельный стабильный идентификатор; `full_name_key` больше не обязательно нормализованное ФИО. Повторный запуск миграции безопасен. Новые связи появляются только после применения реестра.

Перед обновлением сохраняйте резервную копию SQLite штатным способом. Развёртывание на Test и Production — отдельные действия; эта реализация сама их не выполняет. Нет нагрузочной проверки на крупном реестре: список пока использует существующую загрузку заявок по каждому сотруднику, без пагинации. Перед использованием на большой организации стоит измерить задержку на обезличенной копии соответствующего объёма.

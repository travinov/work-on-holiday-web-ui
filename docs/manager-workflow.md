# Руководители и реестр сотрудников

## Импорт

Администратор: **Пользователи → Импорт реестра сотрудников и руководителей** (`/admin/roster`). Доступны шаблоны CSV и Excel `.xlsx`. Заголовки:

| ФИО сотрудника | Рабочая почта сотрудника | Рабочая почта руководителя |
| --- | --- | --- |
| Иванов Иван Иванович | ivanov@example.org | |
| Петров Пётр Петрович | petrov@example.org | ivanov@example.org |

Поддерживаются CSV UTF-8 / Windows-1251 с разделителями запятая, точка с запятой или табуляция; XLSX — первый лист. Лимиты: 5 МБ, 10000 строк сотрудников, 30 МБ распакованного Excel. Макросы и старый формат XLS не поддерживаются.

1. Загрузите файл и проверьте предпросмотр. Изменения ещё не применены.
2. ФИО и рабочая почта сотрудника в файле обязательны. Сначала почта сопоставляется без учёта регистра. Найденные записи обновляются, включая связи подчинения.
3. Если совпадения по почте нет, но в системе есть единственный сотрудник с таким ФИО и без почты, он связывается автоматически: почта заполняется из файла. При сравнении ФИО игнорируются регистр, лишние пробелы и различие Е/Ё. Связывание сохраняет ключ, историю задач, токен, грейд, статус и независимые права администратора. Существующая непустая почта по ФИО не заменяется. Если кандидатов без почты нет, создаётся новый сотрудник.
   При нескольких совпадениях ФИО или нескольких строках файла, претендующих на одну запись без почты, неоднозначные строки пропускаются. Предпросмотр показывает номера строк и причины. Если почта пропущенного руководителя ещё отсутствует в справочнике, строки зависимых сотрудников также пропускаются. Остальные записи можно применить. Исправленные пропущенные строки загрузите повторно.
4. Дубли почты, неизвестные руководители и циклы блокируют применение всего файла. Руководитель может быть в другом месте файла либо в существующем справочнике с почтой. Дубли почты в старой базе требуют исправления справочника до импорта.
5. Проверьте список изменений и пропущенных строк, затем нажмите «Применить записи». Все включённые изменения применяются атомарно; при изменении справочника после предпросмотра требуется новая загрузка. Предпросмотр принадлежит создавшему его администратору, действует 24 часа и применяется один раз. Предпросмотры от прежней версии правил сопоставления нужно загрузить заново.

Пустая почта руководителя означает прямое подчинение **суперпользователю**. Он находится на вершине организации; добавлять его строку или почту в реестр не нужно. В предпросмотре такой руководитель указан как «Суперпользователь». Указанные в файле связи между сотрудниками сохраняют обычный смысл. Отсутствующие в файле сотрудники не удаляются, их руководитель не меняется. Смена рабочей почты не трактуется как автоматический перенос личности: для такого случая требуется отдельная проверка администратором.

Для новых импортированных сотрудников администратор выдаёт токены через существующую кнопку выдачи/перевыпуска на странице «Пользователи». Самостоятельно получить первый токен такой записи по ФИО нельзя. Вход — по рабочей почте и токену; при уникальном ФИО доступен и прежний вход по ФИО. Тёзки входят по почте. При самостоятельной регистрации нового сотрудника обязательны ФИО и рабочая почта. Почта сохраняется в нижнем регистре без пробелов по краям и не может принадлежать другому сотруднику. Повторный вход существующих пользователей, включая записи без почты, не требует заполнения этого поля и не меняет почту.

## Суперпользователь

Войдите с логином и паролем суперпользователя, затем откройте **«Задачи команды — вся организация»** в кабинете администратора или `/manager`. Отдельный токен сотрудника и импорт самого суперпользователя не требуются. Доступ есть и при пустом справочнике.

- По умолчанию выбран охват **«Все уровни подчинения»**: доступны все сотрудники и их заявки, включая старые записи и сотрудников вне импортированного реестра. Период по умолчанию — текущая неделя; для старых заявок задайте диапазон дат.
- **«Прямые подчинённые»** показывает сотрудников без другого руководителя. Их подчинённые доступны в охвате всех уровней.
- Раздел **«Оргструктура»** показывает полный список сотрудников и их непосредственных руководителей независимо от периода и фильтров заявок.
- Фильтры, сохранённые подборки, подробности и выгрузка Excel работают для всей доступной организации. Подборки суперпользователя отделены от подборок сотрудников. Последние применённые условия сохраняются.
- Суперпользователь сохраняет все права администратора: управление пользователями, заявками, отчётами и периодами. Из подробностей задачи можно перейти к управлению заявками выбранного сотрудника.
- Обычный руководитель по-прежнему видит только свою ветвь. Права обычного администратора сами по себе не открывают кабинет всей организации. После выхода суперпользователя или смены его пароля прежняя сессия не даёт глобального доступа, в том числе по старой ссылке выгрузки.

## Руководитель

Наличие хотя бы одного прямого подчинённого автоматически даёт доступ к `/manager` и ссылку «Задачи команды» в кабинете. Удаление последней связи снимает этот доступ. Роль не заменяет администратора; заблокированный/архивированный руководитель не может войти.

- По умолчанию: прямые подчинённые и текущая календарная неделя (понедельник–воскресенье).
- Все уровни: руководители ниже и их сотрудники на любой глубине, группировка задач по непосредственному руководителю.
- Предыдущая/следующая неделя, выбранная неделя либо включительный диапазон плановых дат. Используются актуальные даты и тексты с учётом корректировок.
- Поиск по ФИО, множественный выбор сотрудников и подстрока описания задачи без учёта регистра. Пустой выбор — вся доступная команда.
- Кнопки над формой: «Сохранить фильтр» открывает окно ввода названия и сохраняет текущие условия формы, «Применить фильтр» открывает список личных фильтров: клик по строке выделяет один фильтр, общая кнопка «Применить» подтверждает выбор, урна справа удаляет фильтр своей строки. До выбора кнопка применения недоступна. Для ручного обновления списка используется «Показать задачи». Окна закрываются кнопкой или Escape.
- Последние применённые фильтры и именованные подборки сохраняются в БД учётной записи и доступны при входе с другого компьютера. Повторное имя обновляет подборку; подборку можно удалить. «Текущая неделя» хранится как относительный период и движется по календарю сервера.
- При смене структуры доступ пересчитывается. Сохранённый выбор бывших подчинённых не раскрывает данные; устаревший выбор отмечается на экране. Явное применение формы обновляет выбор.
- Список без задач учитывает период и фильтры сотрудников, но не поиск текста. Отменённая заявка считается существующей. Отсутствие заявок не означает отсутствия выхода на работу.
- Подробности задачи доступны только для действующей подчинённой структуры; изменение чужих задач руководителю не добавлено. Собственные задачи остаются в `/employee`.

## Выгрузка отфильтрованных заявок

**Руководитель:** задайте период, охват, сотрудников, поиск по ФИО и тексту задачи, нажмите «Показать задачи», затем «Выгрузить в Excel» рядом с заголовком списка. Выгружается показанная выборка в том же порядке. Несохранённые изменения полей формы не меняют выгрузку — сначала примените их. Именованные фильтры и переходы между неделями поддерживаются. В файле указывается непосредственный руководитель каждой заявки.

**Администратор:** откройте «Заявки», установите фильтры по ФИО, статусу и плановой дате и нажмите «Выгрузить в Excel». Выгрузка учитывает текущие фильтры без перезагрузки страницы. Пустые фильтры означают весь список; незавершённый ввод даты, как и на экране, не ограничивает выборку по дате.

Файл содержит лист «Заявки» с ID, ФИО, плановыми датой и временем, статусом, условиями выхода, полным текстом задачи, обоснованием, системами, фактическими датой и временем и сведениями о закрытии периодов. Учитываются корректировки; отменённые заявки включаются, если подходят под фильтры. На листе «Фильтры» указаны условия отбора, время формирования на сервере и количество строк. Пустая выборка создаёт файл с заголовками и количеством 0.

Список пересчитывается по актуальным данным при скачивании. Доступ руководителя проверяется заново: бывшие подчинённые и чужие сотрудники не попадают в файл даже по старой ссылке. Изменения фильтров в другой вкладке не меняют ссылку выгрузки уже показанного списка. Скачивание не обновляет сохранённые фильтры, не меняет заявки и не закрывает период. Файлы формируются в памяти и не публикуются в общем списке отчётов.

## Миграция и эксплуатация

При обычном старте приложения создаются три дополнительные таблицы: `app_org_employee`, `app_team_filter`, `app_roster_draft`, плюс индекс руководителя. Старые ключи и данные не переписываются. Для новых сотрудников ключ — отдельный стабильный идентификатор; `full_name_key` больше не обязательно нормализованное ФИО. Повторный запуск миграции безопасен. Связи между сотрудниками меняются после применения реестра.

Системный корень имеет ключ `__superuser__` и не создаёт фиктивного сотрудника, почту или токен. При импорте пустого руководителя этот ключ записывается в `manager_key`. Старые записи без руководителя, включая сотрудников без строки `app_org_employee`, автоматически считаются его прямыми подчинёнными при чтении: повторный импорт не нужен. История заявок и токены сохраняются. Если в старой базе ссылка ведёт на отсутствующего сотрудника, она также отображается как подчинение суперпользователю; новый импорт с неизвестной почтой руководителя по-прежнему отклоняется.

Перед обновлением сохраняйте резервную копию SQLite штатным способом. Развёртывание на Test и Production — отдельные действия; эта реализация сама их не выполняет. Нет нагрузочной проверки на крупном реестре: список пока использует существующую загрузку заявок по каждому сотруднику, без пагинации. Перед использованием на большой организации стоит измерить задержку на обезличенной копии соответствующего объёма.

# ETL для опроса "Выход в выходной"

Скрипт загружает Excel-выгрузки опроса, нормализует поля анкеты и сохраняет данные в SQLite.
Поддерживается дельта-режим: в базу добавляются только новые записи.

## Что обрабатывается

- Лист `Страница 1` из файла опроса.
- Строка заголовков определяется автоматически (по `id / Параметр / Время начала`).
- ФИО (`колонка I`) сохраняется в исходном и нормализованном виде.
- Тип обращения (`колонка J`) нормализуется в:
  - `Подать заявку`
  - `Указать отработанное время`
- Тип оплаты объединяется из вопросов `4` и `5` в поле `payment_type`.
- АС из вопросов `8/10/12/14/16/18` выносятся в отдельную таблицу.
- Для связи по человеку/дате/типу строится `logical_key`.
- Фактическое время через полночь нормализуется: `23:00 - 05:00` на дате `2026-03-28` станет `00:00 - 06:00` на дате `2026-03-29`.

## Структура БД

### `survey_responses`

Основная таблица ответов:

- служебные поля: `response_id`, `source_row`, `source_id`, `start_time`, `duration_raw`, `duration_seconds`, `duration_minutes`
- анкетные поля: `full_name`, `full_name_normalized`, `full_name_key`, `request_type`, `grade_12_plus`, `payment_type`
- поля заявки: `task_description`, `justification`
- даты/время: `planned_work_date`, `planned_work_time`, `actual_work_date`, `actual_work_time`, `target_work_date`
- согласование: `approver`
- системные флаги: `need_additional_system_1..5`
- колонки АС (сырой слой): `system_1..system_6`
- связка: `logical_key`
- технические поля дельты: `row_hash`, `source_file`, `source_file_hash`, `loaded_at`

### `response_systems`

Нормализованный список АС:

- `response_id`
- `system_order` (1..6)
- `system_name`

### `vw_response_summary`

Представление для отчетов: одна строка на ответ с агрегированным списком АС.

### `ingestion_files`

Журнал обработанных файлов выгрузки:

- `file_path`, `file_name`
- `file_hash` (уникальный SHA-256)
- `rows_in_file`, `rows_inserted`
- `file_mtime`, `processed_at`

## Загрузка данных

### Из одного файла

```bash
venv/bin/python src/etl_processor.py \
  --input "Копия 2026-03-24 09.31.24 Выход в выходной.xlsx" \
  --db survey_results.db
```

### Из папки (основной сценарий)

```bash
venv/bin/python src/etl_processor.py \
  --input-dir "/путь/к/папке/с/выгрузками" \
  --db survey_results.db
```

Рекурсивно по вложенным папкам:

```bash
venv/bin/python src/etl_processor.py \
  --input-dir "/путь/к/папке/с/выгрузками" \
  --recursive \
  --db survey_results.db
```

Логика дельты:

- Если файл с тем же `file_hash` уже обрабатывался, он пропускается.
- Если файл новый, в БД добавляются только строки с новыми `row_hash`.
- Уже загруженные строки повторно не вставляются.

## Отчет 1 (для руководства)

Формируется отчет по записям `Подать заявку` с полями:

- `ФИО`
- `Количество выходов за последний месяц`
- `Условия выхода`
- `Перечень задач`
- `Обоснование привлечения`
- `Перечень АС`
- `Плановая дата выхода`
- `Плановое время работ`

Источник: `survey_responses + response_systems`.

Логика:

- В отчет попадают только заявки `Подать заявку`, у которых еще нет фактического выхода.
- Связка заявки и факта: `full_name_key + planned_work_date = actual_work_date`.
- Дубли по одному человеку/дате/типу обращения убираются (берется последняя версия ответа).
- `Количество выходов за последний месяц` считается по фактическим выходам (`Указать отработанное время`) за 30 дней до плановой даты заявки.
- Для строк с условием `Двойная оплата` можно включить валидацию по CSV сотрудников (`--employees-csv`):
  - если `EMP_GRADE_NUM >= 12`, в колонке `Условия выхода` ставится `Двойная оплата (грейд 12+)` (в Excel выделяется красным и `bold`);
  - если у найденного сотрудника пустой `MOBILE_PHONE_TXT`, добавляется колонка `Комментарий` со значением `Отсутствует мобильный номер телефона в Пульс.`.
- Фильтр по дате опционален (`--date-from/--date-to`), если не задан — выгружаются все заявки без факта.

Запуск:

```bash
venv/bin/python src/report_first_management.py \
  --db survey_results.db \
  --employees-csv data/employees_mock.csv
```

С явным периодом:

```bash
venv/bin/python src/report_first_management.py \
  --db survey_results.db \
  --date-from 2026-03-28 \
  --date-to 2026-03-29
```

По умолчанию файл создается в `reports/management_report_1_planned.xlsx`.

## Отчет 3 (для закрытия в Пульсе)

Формируется отчет по записям `Указать отработанное время` с полями:

- `ФИО`
- `Дата фактического выхода`
- `Фактически отработанное время`

Логика:

- В отчет попадают только строки `Указать отработанное время`, где заполнены фактическая дата и фактическое время.
- Дубли по одному человеку и фактической дате убираются (берется последняя версия ответа).
- Фильтр по дате опционален (`--date-from/--date-to`), если не задан — выгружаются все фактические выходы.

## Единый файл отчетов

Для подготовки одного Excel-файла со всеми тремя отчетами используйте:

```bash
venv/bin/python src/build_weekend_reports.py \
  --db survey_results.db \
  --employees-csv data/employees_mock.csv
```

Результат:

- Файл `Отчеты выхода выходные <дата подготовки>.xlsx`
- 3 листа: `Отчет 1`, `Отчет 2`, `Отчет 3`
- На каждом листе:
  - название отчета
  - дата подготовки
  - таблица данных

Разделение логики:

- `Отчет 1` и `Отчет 2`: заявки без фактического выхода.
- `Отчет 3`: фактические выходы.
